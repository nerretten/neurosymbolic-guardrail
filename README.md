# Neuro-Symbolic Financial Guardrail (RB Edition)

**Нейросимвольный шлюз безопасности (Guardrail)** для фильтрации и валидации запросов к финансовым LLM-ассистентам в соответствии с законодательством Республики Беларусь.

Система предотвращает генерацию незаконных индивидуальных инвестиционных рекомендаций, пресекает мисселинг (подмену понятий между защищенными банковскими вкладами и высокорисковыми инструментами) и блокирует обещания гарантированной доходности, сохраняя при этом возможность легального банковского консультирования и финансового просвещения.

---

## 1. Проблематика и назначение системы

Большие языковые модели (LLM) склонны давать прямые советы по покупке ценных бумаг, криптовалют и цифровых знаков (токенов), не учитывая локальные регуляторные ограничения. В юрисдикции Республики Беларусь такие ответы несут прямые правовые риски для финансовой организации:

1. **Нелицензированный инвестиционный консалтинг (Закон РБ № 231-З «О рынке ценных бумаг»):** формирование индивидуальных инвестиционных рекомендаций по ценным бумагам и токенам без статуса профессионального участника рынка ценных бумаг запрещено.
2. **Мисселинг и нарушение гарантий вкладов (Закон РБ № 258-З «О гарантированном возмещении банковских вкладов (депозитов) физических лиц»):** недопустимо позиционировать корпоративные токены или облигации как равнозначную по надежности замену банковскому депозиту, защищенному 100% государственной гарантией.
3. **Обещание доходности (Закон РБ «О рекламе» и Декрет № 8):** запрещено гарантировать будущую доходность по инструментам с рыночным риском.

### Почему обычный классификатор не подходит?

Стандартные нейросетевые фильтры (Prompt Guard / BERT-классификаторы) работают по принципу «черного ящика» и не видят разницы в правовой природе активов. Например, одинаковый интент `INT_GET_ADVICE` («Посоветуй, что открыть/купить»):

* **Запрещен (`DENY`)** для акций, облигаций и токенов.
* **Разрешен (`ALLOW`)** для банковских вкладов (стандартный подбор депозита под срок и цель клиента).

**Neuro-Symbolic Guardrail** решает эту задачу за счет разделения труда:

* **Нейросетевой слой (Neural / NLP)** извлекает из неструктурированного текста с опечатками намерение пользователя (`Intent`) и упоминания финансовых инструментов (`Entities`).
* **Символьный слой (Symbolic / Neo4j Knowledge Graph)** выполняет строгий логический вывод по графовой онтологии права РБ и выносит детерминированный, объяснимый вердикт (`ALLOW` / `DENY`) с трассировкой до конкретной статьи закона.

## 2. Архитектура системы

Сквозной пайплайн обработки запроса (End-to-End Pipeline):

```
[Входящий промпт пользователя]
              │
              ▼
┌─────────────────────────────────────────────────────────────────┐
│ 1. NLP & Entity Linking Layer (nlp_engine.py + entity_linker.py)│
│                                                                 │
│  • Классификация намерения (Intent Classification)              │
│  • Выделение спанов сущностей (GLiNER / N-gram Extractor)       │
│  • Морфологическая нормализация (NLTK SnowballStemmer)          │
│  • Нечеткое связывание с узлами графа (RapidFuzz Token Match)   │
└─────────────────────────────────────────────────────────────────┘
              │
              │ Контракт: {intent_id, asset_ids, class_ids}
              ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. Symbolic Reasoning Layer (rule_engine.py + Neo4j)            │
│                                                                 │
│  • Транзитивный подъем по иерархии классов [:IS_A*0..3]         │
│  • Проверка пересечений с политиками [:RESTRICTS] и             │
│    [:APPLIES_TO_CLASS]                                          │
│  • Проверка кросс-классовых правил (защита от мисселинга)       │
└─────────────────────────────────────────────────────────────────┘
              │
              ▼
     [Вердикт: ALLOW / DENY]
       ├── DENY  ──► Возврат юридически обоснованного отказа + трассировка
       └── ALLOW ──► Передача промпта в генеративную LLM

```

## 3. Описание компонентов проекта

### `main.py` — API-шлюз (FastAPI)

Точка входа микросервиса. Управляет жизненным циклом приложения (`lifespan`): при старте единожды инициализирует пул соединений с Neo4j, загружает локальные веса моделей и синхронизирует индекс сущностей с графом. Предоставляет REST-эндпоинт `POST /ask`.

### `nlp_engine.py` — Модуль понимания естественного языка

Отвечает за перевод сырого пользовательского текста в формальный запрос к графу:

* **Intent Classifier:** сопоставляет текст запроса с семантическими профилями юридически значимых намерений (`INT_GET_ADVICE`, `INT_COMPARE`, `INT_PREDICT_YIELD`, `INT_EDUCATIONAL`).
* **Span Extractor:** выделяет кандидатов на финансовые сущности (названия банков, эмитентов, тикеры, категории активов).

### `entity_linker.py` — Динамический резольвер сущностей (`HybridEntityLinker`)

Реализует принцип **Zero Hardcode** (Single Source of Truth в базе данных):

* При запуске выгружает из Neo4j все актуальные узлы `Asset` и `AssetClass` вместе с биржевыми тикерами.
* Выполняет двуязычный стемминг (`SnowballStemmer`) для отсечения падежных окончаний.
* Использует алгоритмы нечеткого поиска (`rapidfuzz.fuzz.token_set_ratio` и `partial_ratio`) для устойчивости к опечаткам (например, *«токенами билаза»* $\to$ `FINSTORE_BELAZ_01`, *«приарбанке»* $\to$ `BCSE_PRIOR`).

### `rule_engine.py` — Символьный движок правил (Cypher)

Выполняет параметризованный графовый запрос к Neo4j. Реализует три уровня проверок:

1. **Контекстный запрет по классу:** поднимается от конкретного актива или подкласса вверх по иерархии `[:IS_A*0..3]` и проверяет, попадает ли родительский класс под действие политики, блокирующей текущий интент.
2. **Защита от слепого инвестиционного подбора:** если интент `INT_GET_ADVICE` вызван без указания конкретных разрешенных классов («Куда вложить деньги?»), срабатывает блокировка по Закону № 231-З.
3. **Защита от мисселинга:** если в запросе с интентом `INT_COMPARE` одновременно присутствуют государственный гарантированный депозит (`state_guaranteed: true`) и высокорисковый токен (`CLASS_TOKEN`), запрос блокируется политикой `POL_RB_DEPOSIT_COMPARE`.

## 4. Схема и содержимое базы знаний (Neo4j Ontology)

База знаний спроектирована в виде направленного графа со следующими типами вершин и связей:

### 4.1. Таксономия классов финансовых инструментов (`:AssetClass`)

Связь наследования: `(Child:AssetClass)-[:IS_A]->(Parent:AssetClass)`.

| ID узла | Наименование | Родитель (`[:IS_A]`) | Свойства |
| --- | --- | --- | --- |
| `FINANCIAL_PRODUCT` | Финансовый инструмент | — *(Корень)* | — |
| `CLASS_DEPOSIT` | Банковский вклад (депозит) | `FINANCIAL_PRODUCT` | `state_guaranteed: true`, `risk_level: "LOW"` |
| `CLASS_SECURITY` | Эмиссионная ценная бумага | `FINANCIAL_PRODUCT` | `state_guaranteed: false`, `risk_level: "MEDIUM_HIGH"` |
| `CLASS_EQUITY` | Акции хозяйственных обществ (БВФБ) | `CLASS_SECURITY` | `state_guaranteed: false`, `risk_level: "HIGH"` |
| `CLASS_GOV_DEBT` | Государственные облигации РБ (ВГДО) | `CLASS_SECURITY` | `state_guaranteed: true`, `risk_level: "LOW"` |
| `CLASS_TOKEN` | Цифровой знак (Токен ПВТ / Декрет № 8) | `FINANCIAL_PRODUCT` | `state_guaranteed: false`, `risk_level: "HIGH"` |
| `CLASS_CRYPTO` | Криптовалюта | `CLASS_TOKEN` | `state_guaranteed: false`, `risk_level: "EXTREME"` |

### 4.2. Конкретные финансовые активы (`:Asset`)

Связь принадлежности к классу: `(a:Asset)-[:IS_A]->(c:AssetClass)`.

| ID узла | Наименование | Тикер | Класс (`[:IS_A]`) |
| --- | --- | --- | --- |
| `BB_DEPOSIT_STABLE` | Вклад «Стабильный» Беларусбанк | `BYN_DEP_BB` | `CLASS_DEPOSIT` |
| `PRIOR_DEPOSIT_PREMIUM` | Вклад «Премиум» Приорбанк | `BYN_DEP_PRIOR` | `CLASS_DEPOSIT` |
| `BCSE_PRIOR` | Акции ОАО «Приорбанк» | `PRIOR` | `CLASS_EQUITY` |
| `BCSE_MAZ` | Акции ОАО «МАЗ» | `MAZ` | `CLASS_EQUITY` |
| `MINFIN_VGDO_295` | Гособлигации Минфина РБ выпуск 295 | `VGDO_295` | `CLASS_GOV_DEBT` |
| `FINSTORE_BELAZ_01` | Токены БелАЗ выпуск 1 USD | `BELAZ_USD` | `CLASS_TOKEN` |
| `CRYPTO_BTC` | Bitcoin Биткоин | `BTC` | `CLASS_CRYPTO` |
| `CRYPTO_USDT` | Tether USDT | `USDT` | `CLASS_CRYPTO` |

### 4.3. Пользовательские намерения (`:UserIntent`)

* `INT_GET_ADVICE` — Запрос индивидуальной рекомендации по покупке/выбору актива.
* `INT_COMPARE` — Сравнение надежности или выгодности перехода между активами.
* `INT_PREDICT_YIELD` — Запрос гарантии доходности или точного прогноза цены.
* `INT_EDUCATIONAL` — Справочный или образовательный вопрос по механике работы инструмента.

### 4.4. Политики безопасности (`:SecurityPolicy`) и Вердикты (`:Verdict`)

Связи: `(p:SecurityPolicy)-[:RESTRICTS]->(i:UserIntent)`, `(p)-[:APPLIES_TO_CLASS]->(c:AssetClass)`, `(p)-[:RESULTS_IN]->(v:Verdict)`.

| ID политики | Ограничиваемый интент | Целевые классы | Нормативный акт РБ | Причина отказа (`reason`) |
| --- | --- | --- | --- | --- |
| `POL_RB_SECURITIES_231Z` | `INT_GET_ADVICE` | `CLASS_SECURITY`, `CLASS_TOKEN` *(и их потомки)* | Закон РБ № 231-З «О рынке ценных бумаг» | Запрещено предоставлять индивидуальные инвестиционные рекомендации без лицензии профучастника Минфина РБ. |
| `POL_RB_DEPOSIT_COMPARE` | `INT_COMPARE` | `CLASS_TOKEN` + `CLASS_DEPOSIT` *(кросс-правило)* | Закон РБ № 258-З / Декрет № 8 | Недопустимо сравнивать защищенные государством банковские вклады с необеспеченными корпоративными токенами (защита от мисселинга). |
| `POL_RB_YIELD_GUARANTEE` | `INT_PREDICT_YIELD` | `CLASS_SECURITY`, `CLASS_TOKEN` | Закон РБ «О рекламе» | Запрещено гарантировать будущую доходность или прогнозировать котировки инструментов с рыночным риском. |

## 5. Установка и запуск

### Требования

* Docker и Docker Compose
* Python 3.12+
* Poetry

### Шаг 1. Запуск графовой СУБД Neo4j

Создайте файл `.env` в корне проекта:

```env
NEO4J_USER=neo4j
NEO4J_PASSWORD=guardrail_secret_pass_2024
NEO4J_HTTP_PORT=7474
NEO4J_BOLT_PORT=7687

```

Запустите контейнер:

```bash
docker compose up -d

```

### Шаг 2. Установка зависимостей Python

```bash
poetry install

```

### Шаг 3. Предзагрузка локальных весов моделей (Offline-режим)

Чтобы сервер запускался мгновенно и не обращался к Hugging Face Hub при перезагрузках:

```bash
poetry run python preload_models.py

```

### Шаг 4. Запуск FastAPI-сервера

```bash
poetry run uvicorn main:app --reload --port 8000

```

Интерактивная документация Swagger UI доступна по адресу: `[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)`.
