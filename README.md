# Neuro-Symbolic Financial Guardrail (RB Edition)

Нейросимвольный шлюз безопасности (**Guardrail**) для валидации запросов к финансовым LLM-ассистентам в юрисдикции Республики Беларусь.

Архитектура системы исключает вероятностные ошибки («галлюцинации» и дрейф контекста) языковых моделей при применении регуляторных ограничений за счет разделения пайплайна на **нейросетевое извлечение семантики (Information Extraction)** и **детерминированный логический вывод на графе знаний (Symbolic Reasoning)**.

---

## 1. Назначение и соответствие нормативной базе РБ

Система выступает прокси-фильтром между пользователем и генеративной языковой моделью. Она перехватывает неструктурированный запрос, формализует его в предикаты первого порядка и выполняет проверку по следующим нормативным правовым актам:

1. **Закон РБ № 231-З «О рынке ценных бумаг» (ст. 1, 8, 16):**
* Предоставление индивидуальных инвестиционных рекомендаций (выбор конкретных ценных бумаг, определение структуры инвестиционного портфеля) является исключительным правом лиц, имеющих специальное разрешение (лицензию) Министерства финансов РБ на осуществление профессиональной деятельности на рынке ценных бумаг.
* *Реализация в Guardrail:* Любой запрос на подбор, покупку или инвестирование в ценные бумаги (`CLASS_SECURITY`, `CLASS_EQUITY`, `CLASS_GOV_DEBT`) и цифровые знаки/токены (`CLASS_TOKEN`, `CLASS_CRYPTO`) со стороны неавторизованного ИИ-ассистента блокируется (`DENY`).


2. **Закон РБ № 258-З «О гарантированном возмещении банковских вкладов (депозитов) физических лиц»:**
* 100% возврат денежных средств физических лиц в белорусских рублях и иностранной валюте гарантируется Агентством по гарантированному возмещению банковских вкладов только в отношении банковских депозитов (`state_guaranteed: true`).
* Корпоративные облигации и цифровые знаки (токены резидентов ПВТ по Декрету № 8 «О развитии цифровой экономики») не подпадают под государственную систему гарантирования.
* *Реализация в Guardrail:* Пресечение недобросовестных практик продаж (мисселинга). Запросы на сопоставление или перекладывание средств из депозитов в токены/акции блокируются политикой `POL_RB_DEPOSIT_COMPARE`.


3. **Закон РБ № 225-З «О рекламе» (ст. 13) и нормы Декрета № 8:**
* Прямой запрет на обещание или гарантирование будущей доходности по инвестиционным инструментам, подверженным рыночному риску.
* *Реализация в Guardrail:* Запросы с интентом прогнозирования котировок или фиксации прибыли (`INT_PREDICT_YIELD`) для некорреспондирующих активов отсекаются политикой `POL_RB_YIELD_GUARANTEE`.


4. **Легальный периметр консультирования:**
* Консультирование по условиям банковских вкладов (подбор срока, капитализации, отзывности/безотзывности) не является инвестиционным консалтингом и квалифицируется как стандартная информационно-справочная поддержка банковских клиентов. Запросы с интентом `INT_GET_ADVICE` относительно `CLASS_DEPOSIT` пропускаются в LLM (`ALLOW`).

                                  ▼

      │                Эндпоинт: POST /ask                     │

                                  │

      │                                                        │

## 3. Техническая реализация компонентов

### 3.1. `nlp_engine.py` — Извлечение интента и спанов сущностей

Модуль решает задачу первичной декомпозиции текста без использования жестких регулярных выражений:

#### 1. Классификация интента (Semantic Intent Classification)

Вместо классификатора на базе решающих деревьев используется векторное пространство модели `paraphrase-multilingual-MiniLM-L12-v2` (размерность эмбеддинга $d = 384$).

* **Якорные семантические профили ($D_k$):** Для каждого идентификатора интента в памяти хранятся расширенные описания:
* `INT_GET_ADVICE`: *«посоветуй какие активы или бумаги купить, куда вложить средства, инвестиционная рекомендация, что выбрать для покупки»*
* `INT_COMPARE`: *«сравни доходность и надежность инструментов, что выгоднее переложить деньги, отличие вклада от токена»*
* `INT_PREDICT_YIELD`: *«гарантия высокой доходности, точный прогноз роста цены и прибыли, сколько заработаю сто процентов»*
* `INT_EDUCATIONAL`: *«что такое банковский вклад или акции, объясни финансовые термины, как устроен фондовый рынок»*


* **Вычисление вектора:** При инициализации сервиса эмбеддер кодирует якорные описания в нормализованные матрицы векторов $V \in \mathbb{R}^{4 \times 384}$.
* **Инференс:** Текст запроса $T$ переводится в вектор $u = \frac{E(T)}{\Vert{}E(T)\Vert{}}$.
Вычисляется матричное произведение (косинусное сходство):
$$\text{sim}(u, V_k) = u \cdot V_k^T$$


Результирующий интент определяется по максимуму сходства:
$$\text{intent\_id} = \arg\max_k (\text{sim}(u, V_k))$$



#### 2. Извлечение спанов сущностей (Span Extraction via GLiNER)

Вместо традиционных моделей NER, ограниченных жесткими классами `PER/LOC/ORG`, используется **GLiNER (Generalist Model for Named Entity Recognition)**:

* Архитектура модели сопоставляет контекстные представления слов (через двунаправленный энкодер) с текстовыми эмбеддингами произвольных меток (zero-shot/open-vocabulary NER).
* На вход модели подаются целевые типы сущностей: `["акция", "банковский вклад", "облигация", "токен", "криптовалюта", "финансовая организация", "эмитент"]`.
* GLiNER возвращает границы спанов и оригинальный текст фрагментов запроса, удовлетворяющих вероятностному порогу $\ge 0.35$ (например, из фразы *«Посоветуй надежные акции Приорбанка»* извлекаются спаны `["акции"]` и `["Приорбанка"]`).

### 3.2. `entity_linker.py` — Гибридный резольвер сущностей (`HybridEntityLinker`)

Связывает текстовые спаны произвольной длины, содержащие падежные флексии, опечатки или сленг, с точными строковыми идентификаторами (`id`) узлов графа знаний.

#### 1. Синхронизация онтологии (Zero-Hardcode Init)

При запуске класс выполняет Cypher-запрос:

```cypher
MATCH (n) WHERE n:Asset OR n:AssetClass
RETURN n.id AS id, labels(n)[0] AS type, n.name AS name, coalesce(n.ticker, '') AS ticker

```

В оперативной памяти формируется список структур:


$$\text{Entity} = \{\text{id}, \text{type}, \text{name}, \text{norm\_name}, \text{ticker}\}$$

#### 2. Морфологическая нормализация (Стемминг)

Поскольку русский язык является синтетическим (богатая система окончаний), традиционное посимвольное сравнение дает сбои на падежах. Функция `normalize_text(text)`:

* Очищает спан от пунктуации и спецсимволов.
* Применяет алгоритм Мартина Портера для русского и английского языков (`nltk.stem.snowball.SnowballStemmer`), срезая окончания и суффиксы:
* *«акциями»* $\to$ основа `акци`
* *«токенами»* $\to$ основа `токен`
* *«приорбанке»* $\to$ основа `приорбанк`



#### 3. Алгоритм нечеткого сопоставления и ранжирования

Для каждого спана $S$ и каждой сущности $E$ в графе вычисляются две метрики библиотеки `rapidfuzz`:

1. **Token Set Ratio ($M_{ts}$):** выполняет токенизацию, находит пересечение множеств слов основы и считает расстояние Левенштейна между пересечением и остатком. Нивелирует перестановку слов:

$$M_{ts} = \text{fuzz.token\_set\_ratio}(\text{stem}(S), \text{stem}(E))$$


2. **Partial Ratio ($M_{p}$):** ищет оптимальное выравнивание короткой подстроки в длинной строке. Включается только при сопоставимой длине строк ($\vert{}\text{len}(S) - \text{len}(E)\vert{} \le 10$), исключая ложные срабатывания коротких слов со всеми длинными названиями.

**Приоритезация классов (`Class Disambiguation`):**
Если пользователь ввел одиночное категориальное слово (*«акции»*, *«вклады»*), основа которого полностью покрывает токен узла `AssetClass`, сущности присваивается детерминированный бонус веса ($+15.0$), предотвращая ошибочный выбор конкретного единичного актива (например, `BCSE_PRIOR` вместо `CLASS_EQUITY`).

Если финальный скор $\max(M_{ts}, M_{p}) \ge 65.0$, сущность считается распознанной и возвращается ее `id` и `type`.

### 3.3. `rule_engine.py` — Символьный вывод и транзитивный обход графа

Модуль транслирует нормализованные предикаты (`intent_id`, `asset_ids`, `class_ids`) в базу Neo4j.

#### Логика работы графового запроса

Ключевая особенность онтологии — **транзитивность отношений наследования**. Запрещающая политика привязана к абстрактному классу (например, `CLASS_SECURITY`), а пользователь упомянул производный подкласс (`CLASS_EQUITY`) или конкретную бумагу (`BCSE_PRIOR`).

```cypher
MATCH (i:UserIntent {id: $intent_id})

// 1. Подъем от переданных активов к их классам через цепочку IS_A
OPTIONAL MATCH (a:Asset)-[:IS_A*1..3]->(from_asset:AssetClass)
WHERE a.id IN $asset_ids

// 2. Транзитивный подъем от переданных классов к родительским классам
// Диапазон *0..3 включает как сам переданный класс, так и его предков
OPTIONAL MATCH (d:AssetClass)-[:IS_A*0..3]->(direct_cls:AssetClass)
WHERE d.id IN $class_ids

// 3. Формирование единого множества проверяемых классов
WITH i, [c IN (collect(DISTINCT from_asset) + collect(DISTINCT direct_cls)) WHERE c IS NOT NULL] AS target_classes

// 4. Поиск пересечения с политиками безопасности
MATCH (p:SecurityPolicy)-[:RESTRICTS]->(i)
WHERE 
  // Правило 1: Запрет абстрактных запросов ("куда вложить?") без конкретных разрешенных инструментов
  (size(target_classes) = 0 AND p.id = 'POL_RB_SECURITIES_231Z')

  // Правило 2: Прямое или транзитивное попадание класса актива под действие запрета
  OR ANY(cls IN target_classes WHERE (p)-[:APPLIES_TO_CLASS]->(cls))

  // Правило 3: Кросс-классовая защита от мисселинга (сравнение гарантированного вклада и токена)
  OR (p.id = 'POL_RB_DEPOSIT_COMPARE' AND EXISTS {
        MATCH (dep:Asset)-[:IS_A*1..3]->(dep_cls:AssetClass {state_guaranteed: true})
        WHERE dep.id IN $asset_ids AND ANY(c IN target_classes WHERE c.id = 'CLASS_TOKEN')
  })

// 5. Разрешение вердикта
MATCH (p)-[:RESULTS_IN]->(v:Verdict {status: "DENY"})

RETURN 
    v.status AS verdict,
    p.id AS policy,
    p.legal_reference AS law,
    p.reason AS reason,
    [i.id, p.id, v.status] AS trace
LIMIT 1;

```

Если путь в графе замкнулся — возвращается статус **`DENY`** с метаданными статьи закона. Если ни одна блокирующая политика не сработала — система возвращает дефолтный вердикт **`ALLOW`**.

### 3.4. `main.py` — Жизненный цикл сервиса и API-интерфейс

Сервис построен на базе FastAPI и реализует паттерн **Application Lifespan**:

* База данных Neo4j опрашивается один раз при старте воркера.
* Веса ML-моделей загружаются в RAM из локальной папки `./weights` с флагом `local_files_only=True`, исключая сетевые задержки и таймауты.
* Эндпоинт `POST /ask` выполняет строгую типизацию схемы запроса и ответа через Pydantic.

```python
class AskRequest(BaseModel):
    prompt: str

class GuardrailResponse(BaseModel):
    prompt: str
    verdict: str                  # "ALLOW" | "DENY"
    reason: str | None = None     # Юридическое основание отказа
    law: str | None = None        # Нормативный правовой акт
    trace: list[str] = []         # Трассировка графового вывода [Intent, Policy, Verdict]
    nlp_debug: dict               # Служебная информация распознавания
    response_text: str            # Итоговое сообщение для пользователя/LLM

```

## 4. Структура онтологии и базы знаний (Neo4j Schema)

### 4.1. Вершины (Nodes)

```
(:FinancialProduct)
       ▲
       │ [:IS_A]
 (:AssetClass) ──[:APPLIES_TO_CLASS]── (:SecurityPolicy) ──[:RESULTS_IN]──► (:Verdict)
       ▲                                      │
       │ [:IS_A]                              │ [:RESTRICTS]
    (:Asset)                                  ▼
                                        (:UserIntent)

```

1. **`AssetClass` (Класс финансовых инструментов):**
* `id` *(String, PK)*: Системный идентификатор (`CLASS_DEPOSIT`, `CLASS_EQUITY`, `CLASS_TOKEN`).
* `name` *(String)*: Полное юридическое наименование.
* `state_guaranteed` *(Boolean)*: Признак наличия 100% государственной гарантии возврата средств.
* `risk_level` *(String)*: Уровень инвестиционного риска (`LOW`, `MEDIUM_HIGH`, `HIGH`, `EXTREME`).


2. **`Asset` (Конкретный инструмент/выпуск):**
* `id` *(String, PK)*: Идентификатор актива (`BCSE_PRIOR`, `FINSTORE_BELAZ_01`).
* `name` *(String)*: Торговое или маркетинговое наименование инструмента.
* `ticker` *(String)*: Биржевой или платформенный тикер.


3. **`UserIntent` (Намерение пользователя):**
* `id` *(String, PK)*: Код интента (`INT_GET_ADVICE`, `INT_COMPARE`, `INT_PREDICT_YIELD`, `INT_EDUCATIONAL`).
* `description` *(String)*: Описание назначения.


4. **`SecurityPolicy` (Регуляторная политика):**
* `id` *(String, PK)*: Идентификатор правила (`POL_RB_SECURITIES_231Z`, `POL_RB_DEPOSIT_COMPARE`).
* `legal_reference` *(String)*: Ссылка на статью закона или декрета.
* `reason` *(String)*: Эксплицитное текстовое объяснение причины запрета.


5. **`Verdict` (Терминальное состояние):**
* `status` *(String)*: Значение перечисления `DENY` или `ALLOW`.

## 5. Установка, сборка весов и запуск

### 5.1. Требования к окружению

* ОС: macOS (включая Apple Silicon M-серии), Linux, Windows (WSL2).
* Python: `>=3.11, <4.0`.
* Docker Engine `>= 24.0` и Docker Compose.
* Poetry `>= 1.8.0`.

### 5.2. Конфигурация окружения (.env)

Создайте файл `.env` в корне проекта:

```env
NEO4J_USER=neo4j
NEO4J_PASSWORD=guardrail_secret_pass_2024
NEO4J_HTTP_PORT=7474
NEO4J_BOLT_PORT=7687

```

### 5.3. Запуск графовой базы данных

```bash
docker compose up -d
docker ps - узнать контейнер id
docker exec -I <id_контейнера> cypher-shell -u neo4j -p ваш_пароль < init.cypher

```

*Убедитесь, что порты `7474` (Web UI) и `7687` (Bolt binary) доступны.*

### 5.4. Установка зависимостей проекта

```bash
poetry install

```

### 5.5. Предзагрузка моделей в оффлайн-директорию

Для предотвращения повторных скачиваний и сетевых таймаутов запустите скрипт предварительной загрузки весов:

```bash
poetry run python preload_models.py

```

Скрипт сохранит модели в каталог `./weights`:

* `./weights/gliner` — экстрактор спанов сущностей.
* `./weights/embedder` — семантический энкодер интентов.

### 5.6. Запуск микросервиса Guardrail

```bash
poetry run uvicorn main:app --reload --port 8000

```

Swagger-спецификация API доступна по адресу: `[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)`.
